# 心膳 CardioMCD

> 别人算卡路里，我们算钠。
> 一个**心血管视角**的麦当劳点餐顾问 —— 基于真实 MCP 营养数据，按《中国高血压防治指南(2024年修订版)》与 DASH 的钠预算，给每样餐品打红绿灯。

## 它解决什么问题

市面上的麦当劳营养工具几乎都在做同一件事：**算热量、算宏量营养素**。

但对心血管风险人群而言，外食真正的雷区往往不是热量，而是**钠**。一个麦辣鸡腿堡含钠 1208 mg —— 是高血压人群**早餐**钠预算（300 mg）的 4 倍，而它的热量（485 kcal）看起来"还行"。**只看热量会漏掉真正的风险。**

CardioMCD 把判定维度换成临床真正关心的东西：

| 维度 | 是否评分 | 说明 |
|---|:---:|---|
| **钠 sodium** | ✅ | 核心差异化维度，按用户画像动态收紧预算 |
| 能量 energyKcal | ✅ | 单餐能量预算 |
| 总脂肪 fat | ✅ | 单餐脂肪预算（供能比 30% 推导） |
| 碳水 carbohydrate | ✅（仅糖尿病画像） | 默认仅记录不判定，避免对非糖尿病人群过度干预 |
| 蛋白质 protein | 正向参考 | 参与组合推荐排序，不判灯 |
| 钙 calcium | 正向参考 | 仅记录 |
| ~~饱和脂肪酸~~ | ❌ | **MCP 不提供该字段** |
| ~~反式脂肪酸~~ | ❌ | **MCP 不提供该字段** |

> ⚠️ **关于缺失维度**：麦当劳 MCP 的 `list-nutrition-foods` 只返回总脂肪，**不提供饱和/反式脂肪拆分**。
> 本项目**不以总脂肪冒充饱和脂肪、不臆造数值**，而是把缺失显式写进代码、测试与文档。
> 禁得起查：单元测试里有一条 `test_no_saturated_fat_dimension` 专门锁死这件事。

## 指南锚点

阈值不是拍脑袋定的，全部有据可查：

| 阈值 | 取值 | 依据 |
|---|---|---|
| 一般人群每日钠 | **2000 mg/d** | 《中国高血压防治指南(2024年修订版)》：每日食盐摄入量 < 5 g |
| 高血压/心衰/肾病/盐敏感 | **1500 mg/d** | DASH 低钠版 |
| 每日能量 | 2000 kcal/d | 成人参考摄入量 |
| 每日脂肪 | 66.7 g/d | 2000 kcal/d × 30% ÷ 9 kcal/g（供能比上限 30%） |
| 每日碳水 | 275 g/d | 2000 kcal/d × 55% ÷ 4 kcal/g |

分级规则（占单餐预算比例）：

```
≤ 1/3  →  🟢 绿灯
≤ 2/3  →  🟡 黄灯
> 2/3  →  🔴 红灯
```

**短板原则**：单项最终等级 = 各风险维度中的**最差值**。
钠已达红灯的餐品，不会因为蛋白质高就被评为绿灯。

## ⚠️ 为什么不按"三餐均分 ÷3"

早期版本把每日钠预算直接除以 3 得单餐预算。**这是错的**，本项目已修正：

1. 指南只给出**每日**目标，从未规定三餐各占多少 —— ÷3 是凭空假设；
2. 生理学上也不成立：**早餐有能量，但钠负荷远低于午晚餐**。我国膳食钠
   78.34% 来自食盐与调味品（国家食品安全风险评估中心），而早餐一般不含炒菜、
   酱料等高盐烹调食物。按 ÷3 会**系统性高估早餐的钠空间、低估午晚餐**。

正确做法：**餐次必须显式化**。钠与能量使用**不同的餐次权重**（可调参数，非指南数值）：

| 餐次 | 钠权重 | 能量权重 | 高血压(1500 mg/d)单餐钠预算 | 一般(2000 mg/d)单餐钠预算 |
|---|:---:|:---:|:---:|:---:|
| 早餐 breakfast | 20% | 30% | **300 mg** | 400 mg |
| 午餐 lunch | 40% | 40% | **600 mg** | 800 mg |
| 晚餐 dinner | 40% | 30% | **600 mg** | 800 mg |
| 加餐 snack | 10% | 10% | 150 mg | 200 mg |

> 能量 30/40/30 参考《中国居民膳食指南》三餐供能比建议区间；
> 钠 20/40/40 为**工程默认值** —— 见下一节的国际核查：它**不是**指南数值，
> 但有三个独立来源与之高度一致。两者均可通过 `profile` 覆盖。

## 🔍 国际核查：到底有没有"每餐钠"标准？（2026-10-10）

对 WHO / ACC-AHA / ESC / ESH / NICE 及各国学校供餐标准做了检索核对，结论如下。

### 1. 成人高血压：没有一家指南规定"每餐钠"

| 机构 / 指南 | 钠推荐 | 单位 |
|---|---|---|
| WHO 2012（2023 重申） | < 2000 mg/d（食盐 < 5 g/d） | **每日** |
| **2025 ACC/AHA** 高血压指南 | ≤ 2300 mg/d，理想 < 1500 mg/d；重申 DASH；钾 3500–5000 mg/d；新增钾盐替代（中等强度证据） | **每日** |
| **2024 ESC** 血压升高与高血压管理 | 钠 ≤ 2 g/d（≈盐 5 g/d），I 类推荐；新增低钠盐 **IIa / A**（SSaSS、DECIDE-Salt） | **每日** |
| 2023 ESH | ≈ ≤ 2 g/d 钠 | **每日** |
| 2023 NICE | 低钠；未给具体数值 | **每日** |

**没有任何一家给"每餐"数值。** 这正是本项目把餐次权重显式化为可调参数、
而不是假装它是指南数值的原因。

### 2. 但按餐次的钠上限确实存在 —— 在学校供餐（儿童）

| 国家 | 早餐 | 午餐 |
|---|---|---|
| 美国 USDA NSLP/SBP | K-5 **540 mg**（2027-07 起 485）；9-12 640 → 570 | K-5 **1,110 mg**（2027-07 起 935）；9-12 1,280 → 1,080 |
| 英格兰（每餐上限） | — | 小学（7–10 岁）**499 mg**；中学 **714 mg** |
| 日本（学校午餐） | — | 6–7 岁 <600；8–11 岁 <800；12–14 岁 <**1,000 mg** |
| 韩国 | — | 教育部仅提"每餐目标值"，**未纳入法定标准**，各校自定 |

注意：USDA 明确写明 "sodium limits do not apply per day, per meal, or per menu item"，
是**周平均**口径；且是儿童标准，成人不可直接套用。

### 3. 三个独立来源，与本项目的 20/40 高度一致

| 来源 | 早餐 : 午餐 | 比值 |
|---|---|---|
| **本项目默认值** | 20% : 40% | **0.50** |
| USDA 学校餐（K-5） | 540 : 1,110 mg | **0.49** |
| DASH 官方 2000 kcal / 2300 mg 菜单实测 | 早餐 508 mg（22%）: 午餐 905 mg（39%） | **22% : 39%** |
| 中国沈阳市卫健委官方科普 | 「午餐占三餐的 **40%**，一餐食盐 5 g × 40% = 2 g」 | **0.40** |

### 4. 一个**不得采用**的旧口径

国内流行的「每餐盐不超过 2 g、每天不超过 6 g」——源自 **6 g/d 的旧版**指南并做
三餐均分（2×3=6）。指南已更新为 5 g/d，且均分假设正是本项目已废弃的错误。**不采用。**

### 5. 附：中国临床限钠膳食分级（可作画像收紧的参照）

| 分级 | 全日供钠 | 说明 |
|---|---|---|
| 低盐膳食 | ~2000 mg/d | 烹调用盐限 2–4 g |
| 无盐膳食 | ~1000 mg/d | 烹调不加盐 / 酱油 |
| 低钠膳食 | ≤ 500 mg/d | 另忌高钠食物 |

**未指定餐次时**，模块**不做任何餐次分配假设**：钠改为按"占每日预算比例"判定
（**≤10% 🟢 ／ >10% 且 ≤40% 🟡 ／ >40% 🔴**），且**拒绝给出组合推荐**——
因为不知道是哪一餐，就没有可比的单餐钠上限。宁可少给一个答案，也不给一个建立在假设上的答案。

> 40% 这个红灯起点的含义：一件东西就吃掉全天钠预算的四成，已足以单独构成一餐的全部钠负荷。
> ⚠️ 它是本模块自定的分级阈值，**不是指南数值** —— 指南从未定义"单品占每日比例"的分级。

## 两个入口

### 入口一：正常人群（默认，零门槛）

**不需要声明任何病史。** 直接跑即可，默认 `general` 画像：钠 2000 mg/d（WHO 与
《中国高血压防治指南(2024年修订版)》一致的上限）。

```bash
python demo/run_demo.py --meal lunch        # 午餐，钠预算 800 mg
python demo/run_demo.py --meal breakfast    # 早餐，钠预算 400 mg
```

真实输出（一般人群 + 午餐，158 条实时数据）：

```
人群画像：正常人群（未声明任何病史；钠 2000 mg/d）
餐次：午餐（钠权重 40%）→ 单餐钠预算 800 mg

相对最低钠的主食（蛋白 ≥ 15 g）：
  冰牛奶大杯                    钠 154 mg（19%）🟢
  儿童鱼排堡                    钠 442 mg（55%）🟡
  烟肉蛋麦满分                  钠 483 mg（60%）🟡
  蜜汁BBQ风味薄皮脆汁鸡-琵琶腿   钠 547 mg（68%）🔴
  麦香鱼                       钠 556 mg（70%）🔴
```

**对正常人群，本工具给出的是可执行的选择**：前三项都在黄灯以内，可以放心选。

### 入口二：心血管风险人群

用 `--profile` 预设或直接加开关；两者取并集，可细调：

| `--profile` | 含义 |
|---|---|
| `general`（默认） | 正常人群，钠 2000 mg/d |
| `hypertension` | 高血压，钠收紧至 1500 mg/d |
| `diabetes` | 糖尿病，启用碳水维度 |
| `lipid` | 高脂血症，脂肪预算 ×0.8 |
| `renal` | 慢性肾病，钠 1500 mg/d |
| `cardio` | 高血压 + 高脂血症 |

```bash
python demo/run_demo.py --profile hypertension --meal breakfast
python demo/run_demo.py --profile cardio     --meal lunch
python demo/run_demo.py --meal breakfast --hypertension --diabetes   # 预设之上追加
```

> 同一个餐品，两个入口的结论完全不同 —— 见下一节的对照表。

### 一个原则：不把健康人医疗化

正常人群是**默认入口**，不追问病史、不做风险提示、不输出"你可能患病"之类的推断。
病史只在用户主动声明时才启用，且只用于收紧预算。

## 快速开始

```bash
git clone https://github.com/<你的用户名>/cardio-mcd.git
cd cardio-mcd

# 1) 申请麦当劳 MCP Token：https://open.mcd.cn/mcp
export MCD_TOKEN="你的MCP Token"

# 2) 正常人群入口（默认，无需病史）
python demo/run_demo.py --meal lunch

# 3) 心血管风险人群入口
python demo/run_demo.py --profile hypertension --meal breakfast

# 4) 端到端：评分 → 门店 → 菜单 → 真实计价（只读，不下单）
python demo/run_ordering.py --meal lunch

# 5) 打印数字来源标注表
python src/cardio_score.py --sources

# 6) 不联网也能看效果（用 tests 里的真实数据快照）
python demo/run_demo.py --offline --meal breakfast

# 7) 跑测试
python tests/test_cardio_score.py && python tests/test_ordering.py
```

零第三方依赖，标准库即可运行（Python 3.9+）。

### 同一个餐品，餐次不同 → 结论不同

| 餐品 | 钠 | 早餐（预算 300 mg） | 午餐（预算 600 mg） |
|---|---:|:---:|:---:|
| 儿童鱼排堡 | 442 mg | **147% 🔴 红灯** | 74% 🟡 黄灯 |
| 烟肉蛋麦满分 | 483 mg | **161% 🔴 红灯** | 80% 🟡 黄灯 |
| 麦香鱼 | 556 mg | **185% 🔴 红灯** | 93% 🟡 黄灯 |

这就是"餐次必须显式化"的意义：**按 ÷3 均分会得出"儿童鱼排堡占 88%"这个
既不属于早餐也不属于午餐的数字**，对现实没有指导价值。

### 同一个餐品，人群不同 → 结论也不同（两个入口的对照）

同一份「儿童鱼排堡 442 mg」在四个入口下的判定：

| 入口 | 每日钠预算 | 早餐预算 | 判定 | 午餐预算 | 判定 |
|---|---:|---:|:---:|---:|:---:|
| **正常人群**（默认） | 2000 mg | 400 mg | **110% 🔴** | 800 mg | **55% 🟡** |
| 高脂血症 | 2000 mg | 400 mg | 110% 🔴 | 800 mg | 55% 🟡 |
| 高血压 / 肾病 | 1500 mg | 300 mg | **147% 🔴** | 600 mg | **74% 🟡** |
| 高血压 + 高血脂 | 1500 mg | 300 mg | 147% 🔴 | 600 mg | 74% 🟡 |

**两个入口给出的建议完全不同，而这就是本项目的价值**：

- **正常人群 + 午餐** → 有得选：儿童鱼排堡（55%）、烟肉蛋麦满分（60%）都在黄灯内，
  可以直接给"选这两个"这类可执行建议。
- **高血压 + 早餐** → 没得选：最低的儿童鱼排堡仍占 147%。
  此时工具**不假装有解**，而是诚实说"钠几乎必然超标，能做的是选相对最低那一档"。

**这张表最有价值的结论**：在高血压的钠预算下，绝大多数麦当劳主菜单品**一件就爆表**；
真正能装进早餐预算的主食几乎不存在（最低的儿童鱼排堡仍占 147%）。
这是数据给出的结论，不是营销话术 —— 它诚实地说明：**高血压人群在麦当劳吃早餐，
钠几乎必然超标，能做的是选相对最低的那一档，而不是假装找到了一个"健康选项"。**

## 与其他麦当劳 Skill 的区别

| | 常见做法 | CardioMCD |
|---|---|---|
| 判定维度 | 热量、宏量营养素 | **钠优先**，按临床画像 + 餐次动态收紧 |
| 单餐预算 | 日预算 ÷ 3（隐含假设三餐均分） | **餐次显式化**，钠/能量权重分离 |
| 阈值来源 | 自定义 / 未说明 | **明确锚定指南原文**，并标注证据强度 |
| 缺失数据处理 | 用总脂肪近似饱和脂肪 | **显式声明不评分**，并有测试锁死 |
| 数据缺失时 | 给一个看似合理的答案 | **拒绝给出答案**，如实说明假设不成立 |
| 输出 | "这个 500 kcal" | "这个单品就占掉你早餐钠预算的 403%" |
